## 1. الرؤية المعمارية

PolyGlot-StreamBaran مبني على **معمارية الطبقات الأربع المتناغمة** (Layered Architecture)، حيث تنفصل المسؤوليات بوضوح وتتواصل الطبقات عبر واجهات موحدة. هذا يضمن:

- **قابلية الصيانة**: كل طبقة قابلة للاستبدال دون لمس الأخرى.
- **قابلية الاختبار**: كل طبقة لها اختبارات مستقلة.
- **المرونة**: تبديل المزودين (مثلاً Gemini بدلاً من Groq) بتعديل سطر واحد.
- **التوسع**: إضافة لغات أو نماذج أو قنوات تسليم جديدة دون إعادة هيكلة.

## 2. الطبقات الأربع

### الطبقة 1: الالتقاط والتفريغ الصوتي (Ingestion & STT)

```
┌─────────────────────────────────────────────┐
│          AudioExtractor (audio_extractor.py) │
│  - استخراج من URL (yt-dlp)                  │
│  - استخراج من ملف (ffmpeg)                  │
│  - تحويل إلى WAV 16kHz mono                 │
│  - تقسيم الملفات الطويلة                    │
└────────────────┬────────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────────┐
│             STTEngine (stt_engine.py)        │
│  - Whisper عبر Hugging Face API             │
│  - Whisper محلي (fallback)                  │
│  - إخراج TranscriptSegment بطوابع زمنية     │
└─────────────────────────────────────────────┘
```

### الطبقة 2: العقل المترجم والملخص (AI Brain)

```
┌─────────────────────────────────────────────┐
│           AITranslator (translator.py)       │
│  - Gemini 1.5 Flash (افتراضي)               │
│  - Groq LLaMA 3 70B (بديل)                  │
│  - ترجمة دلالية ببرومبت هندسي محكم          │
│  - ترجمة مقطعة للحفاظ على الطوابع الزمنية   │
│  - تلخيص تنفيذي مهيكل (فكرة + نقاط + توصية) │
└─────────────────────────────────────────────┘
```

### الطبقة 3: الأرشيف (Persistence)

```
┌─────────────────────────────────────────────┐
│        DatabaseManager (database.py)         │
│  - Supabase (PostgreSQL مجاني)              │
│  - جدول transcription_records              │
│  - بحث نصي كامل (Full-Text Search)         │
│  - تتبع السجل الكامل لكل عملية              │
└─────────────────────────────────────────────┘
```

### الطبقة 4: التوصيل (Delivery)

```
┌──────────────────┐   ┌──────────────────────┐
│  Telegram Bot    │   │  Streamlit Dashboard │
│  (telegram_bot/) │   │  (web_dashboard/)    │
│  - أوامر سريعة   │   │  - واجهة مرئية       │
│  - استلام ملفات  │   │  - رفع + رابط        │
│  - تسليم فوري    │   │  - تنزيل مباشر       │
└──────────────────┘   └──────────────────────┘
```

        ├──────────────────► [AITranslator.summarize()]

## 4. قرارات التصميم الرئيسية

### 4.1 لماذا Hugging Face API بدلاً من Whisper محلي؟
- **مجاني 100%**: HF يوفر Inference API مجانياً للنماذج مفتوحة المصدر.
- **سرعة**: لا حاجة لتحميل نموذج 3GB على كل تشغيل.
- **مرونة**: يمكن التبديل للنموذج المحلي عند الحاجة (offline mode).

### 4.2 لماذا ترجمة مقطعة وليس كاملة؟
- الحفاظ على **الطوابع الزمنية** الأصلية لكل مقطع.
- منع فقدان الدقة في النصوص الطويلة.
- إمكانية الترجمة المتوازية مستقبلاً (parallel processing).

### 4.3 لماذا Supabase وليس SQLite؟
- قاعدة بيانات سحابية مجانية بالكامل (500MB).
- بحث نصي كامل مدمج (PostgreSQL FTS).
- وصول من أي مكان (بوت + ويب + CLI).
- API تلقائي بدون كتابة backend.

### 4.4 لماذا طبقتا تسليم (تليجرام + ويب)؟
- تليجرام: **فوري** ومحمول، مثالي للاستخدام اليومي.
- ويب: **مرئي** وقابل للتخصيص، مثالي للفِرق والشركات.

## 5. الأمان والخصوصية

- 🔒 **لا تخزين دائم للوسائط**: الملفات الصوتية تُحذف بعد المعالجة.
- 🔒 **بياناتك ملكك**: كل التخزين في حسابك الخاص على Supabase.
- 🔒 **مفاتيح مشفرة**: متغيرات البيئة لا تُكتب في الكود.
- 🔒 **لا تتبع**: لا تُرسل أي تحليلات استخدام لأي طرف ثالث.
